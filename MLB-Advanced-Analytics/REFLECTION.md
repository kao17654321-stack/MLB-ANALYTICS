# Workflow 反思

本次實際執行離線流程，讀取九份來源、檢索 Wiki 並生成15頁 HTML。六項單元測試通過，包括故意加入無效引用 S99 與刪除公式欄位的負向測試。這兩種錯誤是測試注入，不是 LLM 自然生成的錯誤。

1. 哪個節點最常出錯？目前沒有足夠多的自然失敗樣本可判定最常出錯的知識節點。負向測試顯示 Wiki 引用及簡報欄位檢查均能捕捉問題。實際遇到的環境錯誤是 LangGraph 安裝失敗及 Chromium 阻擋 file:// 導覽。
2. 檢查往前移到哪裡？在 Ingest 後、Query 前就檢查來源 ID；在生成 JSON 後、渲染前檢查必要欄位。如此可以在錯誤進入 HTML 前發現，而非只看最終頁面。
3. 是否修改 workflow？設計採用分段驗證及有上限的回傳路徑；為環境限制增加可離線重現的執行模式，並將瀏覽器測試改成直接載入 HTML 內容。這次沒有執行兩輪真實 LLM API 實驗，因此不宣稱錯誤率改善。後續可用 --api 重複執行，記錄失敗節點頻率再比較。
